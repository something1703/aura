# Contributing

## Workflow

Use short-lived branches:

```text
main
  ├── feat/requirements-engine
  ├── feat/failure-model
  ├── feat/cost-engine
  └── feat/aws-validator
```

## Pull request requirements

Every PR should include:

- purpose;
- design impact;
- tests;
- architecture implications;
- security implications;
- cost implications where relevant.

## Architecture changes

If a change alters a major architecture decision, add or update an ADR.
